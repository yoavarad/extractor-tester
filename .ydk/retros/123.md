## What went well
- Python-fixture differential tests (generators emit expected JSON) made parity checkable per module.
- Golden parity passed at the end with zero .NET source changes.
- Parallel orchestrators with explicit `--base origin/main`; the ydk-bookkeeping merge driver kept sibling PR conflicts trivial.

## Friction
- ruff lint failures in the Python fixture generators (PRs #142, #143).
- Debug-only stack overflows from deep JSON nesting (LoaderTests, then ItemComparerTests) were missed because CI builds Release only; fixed with large-stack test threads (PRs #152, #154).
- Real default-1MB-stack overflow when re-serializing depth-2997 values; worker loop, reader threads and runner now run on 256MB stacks (PRs #154, #155).
- Config int-vs-float dump of unset defaults (pydantic does not validate defaults) needed `*Set` flags.
- An API session limit (429) interrupted one orchestrator; resumed from its progress file. Stale orchestrator-progress files for tasks 45 and 94 still say in-progress.

## Decisions
- Parity means Python's actual bytes.
- User-approved deviation: .NET compares items nested deeper than Python's ~496 RecursionError limit instead of failing them (loader limit ~2997 kept).
- `--profile` dropped per ADR-009.
- Other documented deviations: click plain usage errors, .NET stack trace on INTERNAL_FAILURE, container-aware default `--workers`, YamlDotNet error text, HTML LF line endings, .NET exception class names.
